# Расчёт положения и размера зеркала («2 камеры + 1 зеркало»)

Обоснованный расчёт геометрии зеркала для рига `roboson_tools`: угол зеркала, положение
относительно двух камер и объекта, размер зеркального полотна. Использованы параметры,
реально заданные в `config/app_settings.yaml`, и явные геометрические формулы кода
(`silhouette/analytical.py::view_axes`, `silhouette/camera.py::camera_frame`), а не
предположения «на глаз».

## Исходные данные

| Параметр | Значение | Источник |
|---|---|---|
| Азимуты ракурсов | 0°, 45°, 90°, 135° | `config/app_settings.yaml: default_view_angles` |
| Прямые (безмирорные) ракурсы | 0°, 90° | нет переопределения в `camera_distance_mm_by_angle` |
| Ракурсы через зеркало | 45°, 135° | есть переопределение (сейчас — заглушка 2600 мм) |
| Расстояние камера↔объект (прямые ракурсы) | 2000 мм | `camera_distance_mm`, подтверждено пользователем («2 м») |
| FOV камеры вдоль ленты | 68° | `camera_fov_deg` |
| FOV камеры поперёк ленты | ≈54° | производный (сенсор 2592×1944, квадратный пиксель) |
| Запас кадра (margin_factor) | 0.92 | `silhouette/camera.py::_MARGIN_FACTOR` |
| Габарит объекта (правила постановки) | 10×10×10 … 450×320×320 мм | `docs/method.md` |

Азимут θ отсчитывается вокруг продольной оси конвейера X в поперечной плоскости Y–Z
(`analytical.py::view_axes`):

```
v_theta = (0, cos θ, sin θ)   — направление камеры (camera_pos = camera_distance · v_theta)
r_theta = (0, −sin θ, cos θ)  — поперечная ось силуэта в кадре
```

При θ=90° камера стоит на оси +Z (**строго сверху**), при θ=0° — на оси +Y (**сбоку,
горизонтально**). Это подтверждённая пользователем раскладка: прямые камеры ортогональны
(верх + бок), зеркало даёт два диагональных ракурса.

Работаем в 2D-сечении Y–Z (ось X вдоль ленты не участвует в отражении — зеркало считается
плоским прямым «столом», протянутым вдоль всей ленты).

```
C_top  = 2000 · (cos 90°, sin 90°) = (0, 2000)     — камера сверху
C_side = 2000 · (cos 0°,  sin 0°)  = (2000, 0)     — камера сбоку
Object ≈ (0, 0)                                     — референсная точка (ось ленты)
```

## 1. Угол зеркала — точный результат

Закон отражения для плоского зеркала: направление θ отражается в `2φ − θ`, где φ — «пеленг»
линии зеркала (в той же системе отсчёта, что и θ). Для одного зеркала, дающего оба
диагональных ракурса из двух прямых камер, требуется **одно и то же** φ для обеих пар:

```
сторона (0°)  → 135°:   2φ − 0  = 135°  →  φ = 67.5°
верх   (90°)  → 45°:    2φ − 90 = 45°   →  φ = 67.5°
```

Оба уравнения дают одно и то же φ = 67.5° — не совпадение, а единственная раскладка,
геометрически совместимая с сеткой 0/45/90/135° и одним плоским зеркалом (разность прямых
90−0=90° должна равняться разности зеркальных 135−45=90°, что и выполняется). **Это
подтверждает вывод, к которому пользователь пришёл независимо** — верно, менять не нужно.

Наклон зеркальной плоскости: линия зеркала в сечении Y–Z имеет пеленг 67.5° (от оси Y), т.е.
**зеркало наклонено на 22.5° от горизонтали** (67.5° от вертикали). Нормаль зеркала:
`n = (sin 67.5°, −cos 67.5°) ≈ (0.924, −0.383)` (с точностью до общего знака — какая сторона
рабочая, определяется требованием «объект и обе камеры — перед зеркалом», см. ниже).

**Раскладка ракурс↔камера**: боковая камера (0°) через зеркало даёт 135°; верхняя камера
(90°) через зеркало даёт 45°. Каждая камера снимает **два силуэта за один кадр** — прямой в
центре кадра и отражённый в зеркальном пятне сбоку/сверху кадра — отсюда «2 камеры + 1
зеркало = 4 ракурса» без доп. камер.

## 2. Почему единая дистанция 2600 мм для 45° и 135° невозможна

Проверено аналитически: если параметризовать положение зеркала одним сдвигом `t` вдоль
нормали (плоскость `n·(Y,Z) = t`), то длина оптического пути камера→зеркало→объект для КАЖДОЙ
из двух камер — квадратичная по `t` функция с **одинаковым старшим коэффициентом** (обе
получены отражением одной и той же точки-объекта). Значит их разность — линейна по `t`, и
имеет **не более одного** корня. Численно и аналитически этот корень — `t = 0`, т. е. плоскость
зеркала проходит через сам объект — физически невозможно.

**Вывод: путь через зеркало к 45° и путь через зеркало к 135° всегда РАЗНЫЕ длины** ни при каком
реальном (не нулевом) положении зеркала. Текущая заглушка
`camera_distance_mm_by_angle: {45.0: 2600.0, 135.0: 2600.0}` — с одним общим числом на оба
ракурса — не может быть точной ни для какого положения зеркала; нужны **два разных** числа.

## 3. Положение зеркала

### Условие реализуемости

Зеркало отражает только с рабочей стороны — значит объект, камера сверху и камера сбоку должны
находиться **на одной стороне** плоскости зеркала одновременно (иначе одна из камер увидит
тыльную/непрозрачную сторону). Подставив `C_top`, `C_side`, `Object` в уравнение плоскости
`n·(Y,Z) − t`, получаем допустимый диапазон (см. проверочный расчёт):

```
t < −765.4 мм   (зеркало смещено в сторону, противоположную боковой камере, и приподнято)
```

(второе полурешение, `t > 1847.8` мм, соответствует зеркалу ЗА пределами обеих камер —
непрактично).

### Компромисс «размер зеркала ↔ длина оптического пути»

Чем дальше зеркало от оси ленты (|t| больше), тем **меньше** требуется зеркальное полотно, но
**длиннее** оптический путь (хуже освещённость/масштаб изображения, больше габарит рамы рига).
Просчитано по сетке `t`:

| t, мм | путь 45° (верх→зерк.), мм | путь 135° (бок→зерк.), мм | зазор до объекта, мм | зазор до камеры-верх, мм | ширина зеркала (поперёк), мм |
|---:|---:|---:|---:|---:|---:|
| −800  | 2028 | 3532 | 530  | 35   | 1777 |
| −1000 | 2222 | 3923 | 730  | 235  | 1508 |
| −1200 | 2467 | 4316 | 930  | 435  | 1363 |
| **−1500** | **2900** | **4908** | **1230** | **735** | **1234** |
| −1800 | 3384 | 5501 | 1530 | 1035 | 1155 |
| −2000 | 3725 | 5898 | 1730 | 1235 | 1116 |
| −2500 | 4620 | 6890 | 2230 | 1735 | 1048 |

(«зеркало у самой границы», t≈−800…−1000 — минимальные зазоры до камеры/объекта, риск
столкновения корпуса камеры с рамой зеркала; далее выигрыш в размере зеркала быстро выходит на
плато, а путь 135° уже почти утраивает прямую дистанцию 2000 мм.)

### Рекомендуемая рабочая точка: **t = −1500 мм**

Даёт комфортные технологические зазоры (>700 мм от максимального объекта и от камеры) при ещё
разумном оптическом пути (135°-путь = 2.45× прямой дистанции, не на порядок хуже). Положение
плоскости зеркала (ближайшая к оси ленты точка): **Y ≈ −1386 мм, Z ≈ +574 мм** относительно
референсной точки на оси ленты (на 1.39 м в сторону, противоположную боковой камере, и на
~0.57 м выше уровня ленты) — плюс зеркало наклонено на 22.5° от горизонтали (см. §1).

Это **не единственно возможная** точка — она выбрана как практичный баланс; см. таблицу для
пересчёта при других ограничениях рамы.

## 4. Размер зеркала

### Метод

Через приём «мнимое изображение»: путь камера→зеркало→объект по длине равен прямой
камера→зеркало-отражение-объекта; точка пересечения этого отрезка с плоскостью зеркала — это
и есть «пятно», куда должен попасть луч от объекта к данной камере. Требуемый размер зеркала в
этом направлении — по теореме о подобных треугольниках: конус лучей расширяется линейно от
камеры (в вершине — точка) до объекта (в основании — полный габарит объекта), поэтому на
зеркале, отстоящем от камеры на `L1` при полном пути `L1+L2`, требуемый поперечник объекта
масштабируется коэффициентом `k = L1/(L1+L2)`.

При t = −1500 мм: `k_top` (для ракурса 45°, через верхнюю камеру) = 0.329;
`k_side` (для ракурса 135°, через боковую камеру) = 0.691.

### Поперечный размер (вдоль наклонной плоскости зеркала)

Пятна двух камер лежат на РАЗНЫХ участках одного зеркального полотна (верхняя камера бьёт по
зеркалу почти у своей же высоты, боковая — гораздо ниже и дальше по полотну) — расстояние между
центрами пятен ≈ 1004 мм. Плюс половины «поперечников» каждого пятна (диагональ сечения
максимального объекта 320×320 мм ≈ 452 мм, масштабированная k):

```
поперечный размер ≥ 1004 + 452·0.329/2 + 452·0.691/2 ≈ 1004 + 74 + 156 ≈ 1234 мм
```

### Продольный размер (вдоль ленты, ось X)

Зависит от того, нужно ли зеркалу «видеть» объект во всех положениях старт/центр/конец, как
прямым камерам, или только в одном (центр). Оба сценария:

| Сценарий | Покрытие по X у объекта | ×k_top (45°) | ×k_side (135°) | Нужно (максимум) |
|---|---:|---:|---:|---:|
| Только «центр» | 450 мм (сам объект) | 148 мм | 311 мм | **~311 мм** |
| Полный ход старт/центр/конец* | 2201 мм | 724 мм | 1520 мм | **~1520 мм** |

\* Полный ход по X ограничен САМОЙ близкой прямой камерой (2000 мм) через
`belt_offset()` (`silhouette/camera.py`) с `margin_factor=0.92`: `Δx_max ≈ 876` мм в каждую
сторону → полное покрытие `2·876+450 ≈ 2201` мм. Зеркальные ракурсы физически не могут «видеть»
дальше, чем разрешают прямые камеры того же кадра (все 4 ракурса снимаются при одном и том же
положении объекта на ленте).

**Если старт/конец через зеркало не критичны для измерения** (например, годятся только для
прямых 0°/90°, а 45°/135° используются лишь в положении «центр» для дополнения формы) —
продольный размер зеркала можно резко сократить (~310 мм вместо ~1520 мм).

### Итоговая рекомендация по размеру (t = −1500 мм)

| Требование | Поперёк (по наклонной плоскости) | Вдоль ленты (X) |
|---|---:|---:|
| Расчётный минимум (полный ход старт/центр/конец) | 1234 мм | 1520 мм |
| С технологическим запасом (+10–15%) | **~1400 мм** | **~1700 мм** |
| Расчётный минимум (только «центр») | 1234 мм | 311 мм |
| С запасом | **~1400 мм** | **~400 мм** |

Т.е. при требовании «видеть объект в зеркале на всём ходу ленты» зеркальное полотно получается
крупным (≈1.4×1.7 м) — это следствие того, что одно зеркало обслуживает ДВЕ камеры, направленные
почти перпендикулярно друг другу (их «пятна» разнесены по полотну), плюс максимальный объект
450×320×320 мм. Если это неприемлемо по габаритам рамы/стоимости стекла — варианты:
- ограничить зеркальные ракурсы положением «центр» (см. таблицу выше, размер падает ~в 4 раза
  по продольной оси);
- пересмотреть расчётный максимальный габарит объекта для зеркальных видов (не все объекты 450 мм
  длиной реально нуждаются в зеркальных ракурсах);
- разнести на два меньших зеркала (по одному на камеру) вместо одного общего — теряется
  экономия «1 зеркало», но каждое можно сделать компактнее и точнее подогнать по месту.

## 5. Что обновить в конфиге

`config/app_settings.yaml`, вместо заглушки:

```yaml
camera_distance_mm_by_angle:
  45.0: 2600.0   # БЫЛО (общая заглушка)
  135.0: 2600.0
```

на два разных расчётных значения (для рекомендуемой точки t = −1500 мм; **пересчитать**, если
физическое положение зеркала на реальном риге будет отличаться — таблица §3 даёт формулу):

```yaml
camera_distance_mm_by_angle:
  45.0: 2900.0    # через верхнюю камеру (90° → 45° отражением)
  135.0: 4908.0   # через боковую камеру (0° → 135° отражением)
```

## 6. Допущения и что нужно сверить с реальным чертежом рига

- Позиции камер взяты **буквально из формулы кода** (`camera_pos = camera_distance · v_theta`,
  т.е. каждая камера — на дистанции ровно 2000 мм от оси ленты вдоль своей азимутальной оси).
  Реальные крепления (кронштейны, корпуса камер) могут иметь смещения в несколько см — не
  критично для угла зеркала (§1, точный результат), но сдвигает конкретные числа в §3–§4.
- Расчёт ведётся в 2D-сечении Y–Z; зеркало предполагается плоским и однородным вдоль всей длины
  ленты (простая наклонная плоскость, не «бабочка»/сегментированная конструкция).
- Не учтены: толщина оправы зеркала, механические кронштейны, возможное виньетирование по краям
  кадра камеры (за пределами данной геометрической прикидки).
- Ширина реального конвейера/рамы в репозитории не задана — итоговое положение зеркала (§3)
  нужно сверить с фактическим доступным пространством сбоку от ленты.
- Формулы и таблицы (§3) параметризованы по `t` — при изменении любого исходного числа
  (дистанция камеры, FOV, габарит объекта) числа пересчитываются per этим же формулам, вывод
  §1–2 (угол 67.5°, невозможность единой дистанции) от них не зависит.

## 7. Проверка точности габаритов при разном положении зеркала (Короб 300×200×200)

Задача — [[Провести тесты с эмуляцией применения зеркала]]. Проверено эмпирически (не только
аналитически): чувствительна ли точность расчёта габаритов (`check_simple_camera_dims_v3`,
боевые параметры камеры — 2592×1944, FOV 68°, supersample=3) к выбору положения зеркала `t`.

Метод: для каждого `t` из таблицы §3 подставлены расчётные пары дистанций (путь 45°/135° из
той же таблицы) как `camera_distances` в v3, на модели малой коробки (Короб 300×200×200,
истинные габариты 301.0×200.5×200.0 по вершинам меша), перебор yaw 0–157.5° (шаг 22.5°).
Скрипт — `bench_mirror_position.py`.

| t, мм | max err%, весь перебор yaw | mean err% |
|---:|---:|---:|
| −800  | 1.0 | 0.7 |
| −1000 | 1.0 | 0.7 |
| −1200 | 1.0 | 0.7 |
| **−1500 (рекомендовано)** | **1.0** | **0.7** |
| −1800 | 1.0 | 0.7 |
| −2000 | 1.0 | 0.7 |
| −2500 | 1.0 | 0.7 |

**Результат: точность расчёта габаритов на малой коробке НЕ зависит от положения зеркала** во
всём практическом диапазоне t (−800…−2500 мм) — max ошибка 1.0%, mean 0.7% идентичны для всех
семи проверенных положений (см. разбивку по yaw в выводе скрипта — совпадает поточечно). Прямое
объяснение: точность v3 на простой прямоугольной форме уже ограничена растровым/пиксельным
разрешением прямых ракурсов (0°/90°, дистанция фиксирована — 2000 мм) и супсемплингом, а не
удлинением оптического пути зеркальных ракурсов в этом диапазоне (2.0–4.9× прямой дистанции).

**Практический вывод:** положение зеркала (`t`) можно выбирать из соображений компоновки рига
(зазоры, размер полотна, габарит рамы — см. §3), не жертвуя точностью измерения. Рекомендация
**t = −1500 мм** (дистанции 2900/4908 мм) остаётся обоснованной и подтверждённой для переноса
на физический риг — эти значения занесены в `config/app_settings.yaml`
(`camera_distance_mm_by_angle`) и в Webots-симулятор
(`config/layout.yaml: cv_rig.mirror_distance_by_angle`, `mirror_offset: 1.5`).

**Что проверить дополнительно на реальном риге** (не покрыто этой симуляцией): реальное зеркало
вносит собственные оптические искажения (плоскостность стекла, паразитные отражения, потеря
контраста силуэта из-за качества посеребрения) — эмуляция здесь предполагает идеальное плоское
зеркало без потерь. Численная нечувствительность к `t` верна для геометрии/перспективы, но не
гарантирует нечувствительность к качеству реального зеркального полотна.

### Побочная находка: несогласованность в Webots-сцене (исправлено)

При сверке позиции зеркала в `config/layout.yaml`/`tools/gen_world.py` (задача
[[Добавить CV-риг (2 камеры + зеркало) в симулятор]]) обнаружено: `mirror_offset` был равен
1.0 м (не 1.5 м из §3), а формула позиции/поворота объекта-зеркала использовала `mirror_normal_deg`
(пеленг ЛИНИИ зеркала, 67.5°) напрямую как угол смещения и поворота пластины — тогда как
смещение от точки наблюдения должно идти вдоль НОРМАЛИ к плоскости зеркала, т.е. под углом
`mirror_normal_deg ± 90°`, а не вдоль самой линии. Из-за этого объект-зеркало в сцене стоял по
факту в точке, близкой к `t≈0` (плоскость проходит через объект — доказанный в §2 физически
невозможный случай), на стороне камер, а не в реализуемой полуплоскости (t < −765.4 мм, §3).
Это влияло только на визуал (виртуальные камеры для габаритов ставятся напрямую по формуле
отражённого азимута и от позиции объекта-зеркала не зависят) — исправлено в `gen_world.py`
