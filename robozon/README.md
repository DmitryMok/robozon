# Robozon — демонстрация сортировки товаров + CV-отчёт по STL

Два независимых демо для проверки решения, каждое — свой процесс и свой порт
(падение одного не останавливает другое):

1. **Исполнительный механизм** (`http://localhost:8022/`) — Webots-сцена
   конвейера с тремя поворотными шиберами: спавн товаров, эмулированная
   CV-классификация с фиксированной задержкой, трекинг объекта по uid,
   сравнение предсказанного и фактического момента срабатывания шибера
   лучевым датчиком. 3D-вид сцены — прямо в браузере (WebSocket-стрим), окно
   Webots открывать не нужно.
2. **CV-отчёт** (`http://localhost:8010/`) — загрузка произвольного STL,
   полностью математический путь (без Webots, без физики, без реальной
   сенсорной сегментации): сетка из 9 ракурсов рига → геометрический силуэт →
   3D-реконструкция (Exact Polyhedral Visual Hull) → триангуляция габаритов →
   вердикт круглости (критерий G4, Rin/Rout) → итоговая категория (B/C/D).
   Каждый шаг — со своим временем расчёта.

## Структура репозитория

```
robozon/          симулятор + CV-отчёт (этот README — здесь)
roboson_tools/     математика CV-отчёта (силуэты, критерий круглости G4,
                   3D-реконструкция) — обязателен РЯДОМ с robozon/ (sibling-
                   репозиторий), код находит его по относительному пути
                   автоматически, отдельно не ставить/запускать
```

## Установка

```bash
# 1. Системные зависимости (root нужен только на этом шаге)
sudo apt-get update && \
  sudo apt-get install -y python3 python3-pip python3-venv python3-numpy python3-yaml xvfb

# 2. Webots R2025a — в ~/opt/webots, без root (скрипт качает tarball ~150 МБ)
./scripts/install_webots.sh

# 3. Окружение CV-отчёта — venv СТРОГО по пути robozon/.venv-cv (путь зашит в
#    scripts/run_demo_mechanism.sh; свой путь — через переменную окружения
#    CV_REPORT_PYTHON)
python3 -m venv .venv-cv
.venv-cv/bin/pip install -r requirements.txt \
  --extra-index-url https://download.pytorch.org/whl/cu121
```

Версии ПО: Webots R2025a, Python ≥ 3.10.

**GPU не обязателен.** `requirements.txt` как есть тянет CUDA-колёса
torch/torchvision/torchhull (~4-5 ГБ) — они используются только опциональным
уточнением вердикта круглости на пограничных объектах (сустейн-проверка G4).
Если на сервере нет CUDA, эта проверка автоматически отключается (мягкий
`try/except` вокруг `import torch`, без падения приложения) — сами габариты и
3D-реконструкция объекта — чистая CPU-геометрия, GPU для них не требуется
вообще. Чтобы не тянуть CUDA-колёса на сервере без GPU — удалить строки
`torch`/`torchvision`/`torchhull`/`triton`/`nvidia-*` из `requirements.txt`
перед шагом 3 (или поставить CPU-сборку: `pip install torch torchvision` без
`--extra-index-url`). Отчёт сейчас не выводит явную пометку, какой путь
(GPU/CPU) использован для конкретного расчёта — известное ограничение.

## Запуск

```bash
./scripts/run_demo_mechanism.sh            # с дисплеем (десктоп/WSLg)
./scripts/run_demo_mechanism.sh --headless # сервер без дисплея (через xvfb-run)
```

Один скрипт поднимает оба демо. В браузере:

- **http://localhost:8022/** — исполнительный механизм: 3D-вид сцены + панель
  управления (спавн, ручное/автоматическое управление шиберами, список
  объектов со статусами, счётчики точности синхронизации).
- **http://localhost:8010/** — CV-отчёт: загрузка STL (drag&drop или через
  диалог) → галереи изображений по шагам (сетка ракурсов / силуэт /
  реконструкция) → сводка (категория B/C/D, коэффициент k, ось, время
  каждого шага).

При доступе к серверу удалённо — пробросить оба порта ssh-туннелем:
```bash
ssh -L 8022:localhost:8022 -L 8010:localhost:8010 user@server
```

## Проверка, что всё поднялось

```bash
curl http://localhost:8022/           # HTML панели исполнительного механизма
curl http://localhost:8010/api/health # {"ok": true}
```

## Известные особенности

- Первый запуск Webots может занять ~20 секунд.
- Предпросмотр CV-камеры на панели механизма (переключатель «cvTopLive», по
  умолчанию выключен) при первом запросе сразу после старта Webots иногда
  возвращает 503 — холодный рендер шейдеров под headless; повторный запрос
  проходит.
- При первом запуске в логе Webots возможны кратковременные предупреждения о
  недоступности мешей/текстур панели (`Connection refused`) — прогрев
  локального HTTP-сервера панели; сцена продолжает работать штатно, повторный
  запуск не требуется.
- Сегментация в CV-отчёте — точный геометрический силуэт STL, не результат
  реальной сенсорной CV-сегментации и не SAM3 (указано и в самом отчёте).

## (Локальная разработка) Старая сцена sorting_line — не входит в финальную сдачу

Живая интеграция CV в основную сцену сортировки — заморожена (см. вики,
«План финализации сдачи»), но код и математика рига остаются источником
переиспользуемого кода. Ниже — оригинальная документация этой сцены, только
для локальной отладки.

### Что видно в демо

В браузере — веб-панель с кнопками типов товаров, ручным управлением
шиберами и встроенный 3D-вид. Нажатие кнопки кладёт товар на конвейер A
(1 м/с) в случайной ориентации (включая «на боку»/«вверх ногами» — для
реалистичной физики и разнообразия под будущую демонстрацию CV). Система
классифицирует товар и поворотный шибер направляет его:

- **B — зона основного сортировщика** (прямо, на приёмный конвейер): габариты
  в пределах 450×320×320 мм и нет круга в сечении;
- **C — ролл-кейдж негабарита** (шибер 1): габариты вне допуска;
- **D — ролл-кейдж доупаковки** (шибер 2): круг в сечении (k = r/R > 0.7).

Категории всех 11 тестовых STL-моделей заданы в `config/objects.yaml`.

Шиберами можно управлять и вручную (кнопки «→ B/C/D» и «Авто» в панели или
`POST /api/route`/`POST /api/auto`) — удобно для точечной проверки конкретной
позы/траектории без ожидания автоматики.

Кнопки «Начать/Остановить запись» пишут видео основного 3D-вида в файл
(требует `ffmpeg`, см. установку); готовая запись появляется в панели
ссылкой на скачивание. `ffmpeg` нужен только для локальной записи
материалов — на сервере хакатона ставить его не нужно: без него панель
вместо кнопок показывает сообщение, что запись недоступна, и это никак
не влияет на работу основного решения.

### Исполнительный механизм

Два поворотных шибера (plow diverter) над лентой на вертикальных осях
(RotationalMotor). Товар всегда остаётся на приводной ленте: развёрнутый под 30°
щит перекрывает ленту, лента прижимает товар к щиту, и он соскальзывает вбок
в ролл-кейдж. Ключевые инженерные решения (выведены итерациями в симуляции):

- **угол щита 30°**: при α > 45° боковой прижим N·cos α меньше бокового трения
  о ленту — товар клинит; при 30° соскальзывает любой из тестовых товаров;
- **наклон щита верхом на товар (~11°)**: прижимает товар к ленте — исключает
  опрокидывание на щит и заклинивание под нижней кромкой;
- **нет «мёртвых» поверхностей**: за краем ленты нет статичных полок, на
  которых товар мог бы запарковаться;
- **нештатные ситуации**: если товар застрял — у щита или где угодно ещё на
  ленте (например, после приземления в неудачной случайной ориентации) —
  супервизор его расталкивает: у щита коротко «встряхивает» щит, иначе толкает
  сам объект (событие `nudge` в журнале, `webots/controllers/supervisor_main`);
- **зона фиксации доставки** — засчитывается по факту пересечения товаром
  стенки бокса/лотка, прилегающей к конвейеру, в пределах её ширины (высота
  намеренно не проверяется — иначе штабель из нескольких товаров в одном
  боксе не даёт верхним засчитаться, хотя они уже на месте, см. `sim/router.py`);
- **очередь шиберов — по зонам, не общая**: B и D — независимые лотки,
  каждый обслуживает свою очередь (FIFO) и не блокирует другую зону; лоток
  освобождается сразу по входу объекта в зону, не дожидаясь итогового
  подтверждения — иначе он может лишнее время простоять развёрнутым и
  случайно перехватить чужой объект, идущий следом по той же ленте (актуально
  для частого спавна нескольких товаров подряд).

**Известные пограничные случаи** (не устранены, требуют изменения геометрии
участка — см. обсуждение):
- `pouf` (Ø490 мм, почти вровень с шириной ленты 500 мм) иногда застревает на
  боковом бортике ленты при неудачной случайной ориентации появления;
- лоток D физически ближе к появлению товара, чем лоток B; при частом спавне
  нескольких D-товаров подряд лоток D может успеть захватить и B-товар,
  проезжающий мимо в этот момент (щит — просто наклонная стенка, не
  различает «свой/чужой» объект). Не проявляется при обычном темпе (по
  одному товару за раз) — только при агрессивном частом спавне однотипных
  D-товаров подряд.

### Установка на чистый сервер (Ubuntu 22.04+/WSL2)

```bash
# 1. Системные зависимости (root нужен только на этом шаге;
#    xvfb — только для сервера без дисплея)
sudo apt-get update && sudo apt-get install -y python3 python3-numpy python3-yaml xvfb

# 1a. (опционально, только для локальной записи видео материалов —
#      на сервере хакатона не нужно) sudo apt-get install -y ffmpeg

# 2. Webots R2025a — в ~/opt/webots, без root (скрипт качает tarball ~150 МБ)
./scripts/install_webots.sh

# 3. Проверка логики без Webots
python3 tests/test_sim.py
```

Версии ПО: Webots R2025a, Python ≥ 3.10, numpy ≥ 1.24, PyYAML ≥ 6.0.
Установка в нестандартный путь — через переменную `WEBOTS_HOME`.

### Запуск

```bash
./scripts/run.sh              # с дисплеем (десктоп/WSLg)
./scripts/run.sh --headless   # сервер без дисплея (через xvfb-run)
```

Скрипт сам генерирует мир из `config/` и поднимает: панель на `:8008`,
стриминг-сервер Webots на `:1234` (порты меняются в `config/layout.yaml` -> `http`).

Дальше в браузере: **http://localhost:8008/** — панель управления + 3D-вид.
Замечания:
- решение полностью офлайн: 3D-вьюер (`web/wwi/`) и STL-меши раздаются
  локальным сервером панели, интернет не нужен ни серверу, ни браузеру
  (вьюер один раз векторится скриптом `tools/fetch_wwi.py`, в репозитории
  уже лежит готовый); запуск на сервере без сети проверяется так:
  `./scripts/run.sh --headless` → `curl localhost:8008/api/status`
  должен вернуть JSON без ошибок и таймаутов в логе Webots;
- при доступе к серверу извне пробросить порты 8008 и 1234 ssh-туннелем:
  `ssh -L 8008:localhost:8008 -L 1234:localhost:1234 user@server`
  (туннель обязателен: 3D-вид и меши адресуются через localhost);
- первый запуск Webots может занять ~20 с;
- при запуске с дисплеем (без `--headless`) у Webots уже есть нативное окно —
  панель по умолчанию НЕ подключает 3D-вид в браузере (иначе сцена рендерится
  дважды впустую); включить его можно вручную переключателем «3D-вид» в
  шапке панели (запоминается в браузере). При `--headless` подключается
  автоматически — это единственный способ увидеть сцену.

### Проверка

```bash
python3 tests/test_sim.py        # unit-тесты логики (без Webots)
python3 scripts/test_e2e.py      # сквозной тест: все 11 типов -> свои зоны (нужен запущенный run.sh)
python3 scripts/test_e2e.py --types bottle,box_large   # выборочно
```

Эталонный результат e2e: `ВСЕ 11 ТИПОВ ДОСТАВЛЕНЫ ВЕРНО`. Товар появляется в
случайной ориентации при каждом спавне — изредка (см. «Известные пограничные
случаи» выше) `pouf` может не уложиться в таймаут теста при неудачном
случайном развороте; перезапуск обычно проходит чисто.

### Управление экспертом (API)

- `POST /api/spawn {"type": "bottle"}` — положить товар на ленту;
- `GET /api/objects` — каталог типов и целевых зон;
- `GET /api/status` — состояние: объекты, шиберы, журнал, счётчики;
- `POST /api/reset` — очистить сцену;
- `GET /api/screenshot` — кадр с обзорной камеры (JPEG);
- `POST /api/route {"zone": "B"}` — ручное управление шиберами (B/C/D),
  отключает автоматическую маршрутизацию до `/api/auto`;
- `POST /api/auto` — вернуть автоматическое управление шиберами;
- `POST /api/record/start` / `POST /api/record/stop` — запись видео основного
  3D-вида (`Supervisor.movieStartRecording`, требует системный `ffmpeg` —
  см. установку выше); состояние — поля `record_state`
  (`idle`/`recording`/`encoding`/`ready`/`failed`) и `record_file` в
  `/api/status`; готовый файл — `GET /records/<file>.mp4`;
- `GET /api/record/list` — список сохранённых записей (`/tmp/robozon_records`).

### Структура

```
config/objects.yaml   товары: STL, масса, физическая оболочка, категория
config/layout.yaml    геометрия участка, шиберы, зоны — единый источник правды
tools/gen_world.py    генерация мира Webots из layout.yaml
tools/prepare_stl.py  обработка STL (мм->м, ориентация) + габариты и коэффициент круга
sim/                  логика без Webots: классификатор (интерфейс под CV), маршрутизация
webots/               мир, PROTO конвейера и ролл-кейджа, контроллеры
web/index.html        панель управления
scripts/              запуск и e2e-тест
assets/               STL исходные и обработанные
```

Вся настройка — в YAML: типы товаров, категории, скорость ленты, позиции
шиберов и кейджей, зоны фиксации. После правки `layout.yaml` перезапустить
`run.sh` (мир перегенерируется автоматически).
